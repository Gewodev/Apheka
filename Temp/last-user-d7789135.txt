3. Mensajes y partes

La idea central, que usan assistant-ui y AI SDK: un mensaje del asistente es una lista de partes tipadas (reasoning, text, tool-call, source, file), no una cadena de texto. Tú decides cómo pintar cada una:

tsx
<MessagePrimitive.Parts>
  {({ part }) => {
    if (part.type === 'reasoning') return <Reasoning {...part} />;
    if (part.type === 'text')      return <Response>{part.text}</Response>;
    if (part.type === 'tool-call') return part.toolUI ?? <ToolFallback {...part} />;
  }}
</MessagePrimitive.Parts>

Esto sigue el patrón documentado de assistant-ui, donde las partes de tipo tool-call exponen la UI registrada para esa herramienta, o null si no hay ninguna. 
assistant-ui

Diferencias visuales entre usuario y asistente:

Usuario: burbuja o bloque sutil con fondo tintado, alineado a la derecha, tipografía sans.
Asistente: sin burbuja ni avatar pesado. El texto fluye sobre el fondo de la página, en serif.

7. Tablas, código y exportación

Streamdown resuelve casi todo. Por defecto ofrece botón de copiar en bloques de código, de descargar en tablas, y controles de copia, descarga SVG, pantalla completa y zoom en diagramas Mermaid. Se configura así: 
smithery

tsx
<Streamdown isAnimating={status === 'streaming'}
  controls={{ code: true, table: true, mermaid: { copy:true, download:true, fullscreen:true } }}>
  {part.text}
</Streamdown>

Estilo de tabla “limpio”: sin bordes verticales, encabezado en gris pequeño en versalitas o negrita ligera, línea fina entre filas, overflow-x:auto en un contenedor para que la tabla nunca rompa el ancho del chat, y los botones de copiar/descargar visibles solo al pasar el cursor.

Para exportar más allá de lo que da Streamdown:

Mensaje completo: botón “Copiar” (Markdown) y “Descargar .md”.
Tabla: convertir a CSV o XLSX en el cliente.
Documento: exportar a PDF o DOCX desde el servidor (por ejemplo, con una librería de generación de DOCX y un renderizador de PDF) y devolver una URL de descarga.
